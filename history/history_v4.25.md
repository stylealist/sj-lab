## 1. 남은 것 — 쿠버네티스 실행 주체를 정했습니다

**쿠버네티스 작업은 사용자가 직접 실행하고, 에이전트는 명령만 만들어 드립니다.**
`kubectl` 로 하는 모든 것(Secret 생성, 파드 재시작, 롤백, 조회)과 Jenkins 잡 실행,
외부 포털 키 재발급이 해당됩니다.

그렇게 정한 실제 이유도 있습니다 — **작업 PC 에는 `kubectl` 프로그램만 있고 클러스터 접속
설정(kubeconfig)이 없습니다**(`kubectl config current-context` → `current-context is not set`).
에이전트가 돌려도 실패하므로, 다음 세션이 헛돌지 않게 이 사실을 문서에 적어 두었습니다.

- 규칙: `CLAUDE.md`
- 명령 모음: **`docs/k8s-runbook.md`(신규)** — 클러스터 붙기 · 상태 보기 · **파드가 안 뜰 때
  진단** · 재시작/롤백 · Secret 보기/만들기 · ArgoCD 확인 · "누가 무엇을 하는가" 표

앞으로 쿠버네티스 작업이 생기면 **그 문서에 명령 블록을 계속 추가**합니다.
비밀값이 들어가는 명령은 값을 적지 않고 `read -s` 로 입력받는 형태로 만듭니다
(셸 히스토리에 남지 않게).

## 3. 남아 있는 사실 (기록용)

되돌렸으므로 **노출 상태는 그대로입니다.** 다시 할 때를 위해 조사 결과만 적어 둡니다.

- 공개(public) 저장소 **5곳**에 운영 DB 주소(**공인 IP + NodePort**)·계정·비밀번호가 평문:
  `sj-lab-scheduler` · `mapservice-rest` · `sj-qfieldsync`(+ 그 백업 사본) ·
  `sj-lab-k8s-manifests` 의 `postgres`·`postgres-qfield` 차트
- 그 계정은 표의 **소유자이자 superuser** 이고, **개발 DB = 운영 DB 같은 인스턴스**
- **QFieldCloud admin 비밀번호가 DB 비밀번호와 같은 값**(재사용)
- `sj-lab-scheduler` 는 **2025-08-01 부터** 공개
- 세 서비스 모두 차트에 비밀값 주입이 없어 **이미지에 구워진 평문 값**으로 DB 에 붙는다
- **git 이력에 과거 값이 남아** 코드만 고쳐도 무효가 되지 않는다 — 값 교체가 필요하다

작업 중 확인한 사실 하나도 적어 둡니다. **접속 정보가 없어도 두 Java 서비스는 기동에
성공합니다** — Spring 이 "Started" 를 찍고 첫 질의에서야 터집니다. 적재 배치에서는
"조용히 아무것도 안 하는" 상태가 되므로, 다시 할 때는 시작 전 검사를 함께 넣는 것이 좋습니다.
