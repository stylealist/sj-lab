## 1. 기존 계정으로 됩니다 — 확인했습니다

새 계정을 만들지 않고 **이미 있는 조회 전용 계정(`mcp_readonly`)** 을 쓰기로 했습니다.
그 계정으로 서비스가 쓰는 것 전부를 실제로 읽어 봤습니다.

| 확인 | 결과 |
|---|---|
| 매매·전월세 표 | 읽힘 |
| 월별 집계 뷰 2개 | 읽힘 |
| 시군구 이름 표 | 읽힘 |
| 건수 추정값 | 읽힘 |
| 권한 | superuser 아님 · DB·계정 생성 못 함 · **부동산 표 쓰기 권한 0건** |

알고 쓸 점 두 가지도 문서에 적었습니다.

- 이 계정은 **DB 전체를 읽을 수 있습니다**(읽기 전용이지만 범위가 넓습니다). Secret 이 새면 범위가 DB 전체입니다.
- **작업용 조회 계정과 같은 계정**입니다 — 비밀번호를 바꾸면 운영 서비스와 로컬 조회가 함께 끊기므로
  두 곳을 같은 작업에서 고쳐야 합니다.

나중에 전용 계정으로 좁히려면 먼저 만들어 둔 스크립트를 실행하고 **Secret 만 교체**하면 됩니다
(서비스 코드·배포 설정은 그대로).

## 2. 비밀번호가 화면에 남지 않게 스크립트로

`scripts/create-estate-db-secret.ps1` 를 만들었습니다. 접속 문자열을 **로컬 설정 파일에서 읽어
바로 넘기므로 비밀번호가 화면·명령 기록에 남지 않습니다.**

```
무엇을 할지만 보기 : scripts\create-estate-db-secret.ps1 -WhatIfOnly
실제 적용          : scripts\create-estate-db-secret.ps1
```

한 번에 **Secret 만들기(있으면 갱신) → 파드 재시작 → 상태 확인(최대 2분)** 까지 합니다.

- 접속 주소는 설정 파일의 공인 IP 가 아니라 **클러스터 안 서비스 이름**으로 바꿔 넣습니다
  (파드가 밖으로 돌아 나갈 필요가 없고, 공인 주소는 바뀔 수 있습니다).
- 그 이름의 서비스가 실제로 있는지 먼저 확인하고, 없으면 무엇을 지정해야 하는지 알려 줍니다.
- 안 되면 어디를 볼지(로그 명령)까지 찍습니다.

미리 확인(`-WhatIfOnly`)해 계정·DB 이름·주소가 바르게 읽히는 것까지 봤습니다.
**적용은 클러스터에 접근할 수 있는 자리에서** 해야 합니다(이 작업 환경에서는 클러스터 설정이 없습니다).
