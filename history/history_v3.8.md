## 한 줄 요약

키를 **직접 받고 직접 붙이던 것**에서, **로그인하면 이미 있고 화면이 알아서 붙여 주는 것**으로 바꿨습니다.
그리고 키 없는 호출을 막아 하루 한도가 실제로 걸리게 했습니다.

## 1. 운영에서 "Failed to fetch" — 제가 만든 문제였습니다

v3.5에서 공개 API를 외부에 열 때 CORS를 `GET`·`OPTIONS`만 허용하게 열었는데,
그 범위에 **키 발급·폐기 경로까지 같이 들어가** 버렸습니다. 키 API는 `POST`·`DELETE`를 쓰니
브라우저의 예비 질문이 막혀 화면에는 "Failed to fetch"만 떴습니다.

키 경로만 따로, 그리고 **더 앞에** 열어 해결했습니다(설정은 처음 맞는 규칙이 이깁니다).

| 경로 | 허용 |
|---|---|
| `/open-api/keys`, `/open-api/keys/**` | sj-lab 주소 + 로컬, `GET`·`POST`·`DELETE`, 로그인 헤더 허용 |
| `/open-api/**` (그 밖의 공개 조회) | 아무 사이트에서나, `GET`만 |

## 2. 키는 계정당 1개, 자동으로 배정

발급 버튼을 없앴습니다. **로그인하면 이미 키가 있습니다.**

| | 전 | 후 |
|---|---|---|
| 키 받기 | "발급" 버튼 누르기 | 로그인하면 자동 배정 |
| 개수 | 여러 개 쌓임 | **1개 고정** |
| 바꾸기 | 발급 버튼 또 누르기 | "키가 유출됐다면 — 새 키로 바꾸기" 한 줄 |

여러 개를 둘 수 있으면 "지금 어디서 어떤 키를 쓰는지" 알 수 없고, 하나를 버리면 쓰던 곳이
조용히 멈춥니다. 그래서 1개로 고정했습니다.

## 3. 키 값을 전체로 보여 줍니다 (방침 변경)

전에는 보안을 위해 **발급되는 순간에만** 보여 주고 DB에는 지문(해시)만 남겼습니다.
그런데 **다른 서버·프로그램에서 이 API를 부를 때 키를 모르면 쓸 수가 없다**는 지적을 받고 방침을 바꿨습니다.

- 이제 키 원문도 저장하고, 화면에서 언제든 전체 값을 보고 **복사**할 수 있습니다.
- 대신 **확인은 계속 지문으로만** 하고, 로그에는 키를 찍지 않습니다.
- 이 키로 할 수 있는 일은 **조회 전용 12개 API와 하루 한도(1000회) 소진**까지입니다. 쓰기·삭제는 없습니다.

> DB 작업이 필요합니다: `db/api/openapi_api_key_plain.sql` (담당자 실행). 실행 전에도 화면은
> 그대로 동작하며, 그동안은 키 앞자리만 보입니다.

## 4. 키 없는 호출을 막았습니다

```
전   키 없이 불러도 200  →  한도가 의미 없었음
후   키도 로그인도 없으면 401 API_KEY_REQUIRED
```

키를 확인할 수 없는 상태(DB 미준비)에서는 **그냥 통과시키지 않고 503**을 냅니다.
"필수"가 조용히 풀려 아무나 부르게 되는 일을 막으려고요.

## 5. 화면 정리

- **내 API 키**: 키 값 + 복사 버튼, 오늘 사용량을 숫자와 막대로. 만들기 버튼 없음.
- **오늘 사용량이 바로 갱신**됩니다 — 실행해 보기를 누를 때마다 다시 읽습니다(전에는 0에 머물러 키가 안 쓰이는 것처럼 보였습니다).
- **각 API의 파라미터에 `apiKey`가 보입니다.** 내 키가 자동으로 채워져 있어, 주소를 그대로 복사하면 다른 곳에서도 바로 동작합니다.
- **필수 파라미터가 위, 선택이 아래**로 정렬됩니다.
- **값이 비어도 버튼을 잠그지 않습니다.** 눌러 보면 응답에 무엇이 빠졌는지 나옵니다 — 그게 배우기 쉽습니다.

```
bbox 안 넣고 실행   400  필수 파라미터가 없습니다: bbox
키 비우고 실행      401  API 키가 필요합니다…
시설물 ID 안 넣음   400  경로 값이 없습니다: totalId
```

## 겪은 것 둘

- **경로 값(`{totalId}`)을 비운 채 보내면 서버까지 가지도 못합니다.** 웹서버(Tomcat)가 주소의
  중괄호를 먼저 거부해 **내용 없는 400**만 돌아옵니다. 그래서 그 경우만 화면이 메시지를 직접
  적어 주도록 했습니다. 서버 쪽 확인도 함께 넣어 뒀습니다(다른 방식으로 부를 때를 대비).
- **조회 전용 계정에서 키 원문을 가리려던 설정이 효과가 없었습니다.** 그 계정이 "모든 표 읽기"
  역할을 가지고 있어 컬럼 단위 차단이 덮이지 않습니다. 스크립트에 사실과 확인 방법,
  정말 가릴 때의 명령을 주석으로 남겼습니다.
