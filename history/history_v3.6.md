## 켜는 과정에서 도와드린 것

처음 시도한 Secret 생성 명령이 셸 오류(`event not found`)로 실패했습니다.
원인은 `username='stylealist'` 의 **여는 따옴표 하나가 빠진 것**이었습니다 —
그 때문에 뒤따르는 비밀번호가 따옴표 밖으로 나가고, `!` 가 bash 히스토리 확장으로 해석됐습니다.
따옴표를 채워 해결했고, 비밀번호를 명령줄에 남기지 않는 방법(파일로 넣고 삭제)도 함께 안내했습니다.

## 어떻게 확인했나

배포 전 — `helm lint` 통과, `helm template` 에서 세 환경변수가 Secret 의 `url`·`username`·`password` 를
참조하도록 렌더링되는 것 확인.

배포 후 — 체험용 계정으로 **실제로 끝까지** 해봤습니다.

```
로그인(체험용 계정)        OK
키 발급                   OK   (원문은 발급 응답에 한 번만)
그 키로 API 호출 3회       200 · 200 · 200
사용량                    오늘 3 / 1000, 마지막 사용 시각 기록됨
가짜 키로 호출             401
키 없이 호출               200  (기존 정책 유지)
키 폐기                   OK   → 남은 키 0개
```

확인용으로 만든 키 2개는 모두 폐기했습니다(폐기는 행을 지우지 않고 사용 안 함으로 표시하는 방식이라,
DB 에 `use_yn = 'n'` 인 행 2개가 남아 있습니다).

한글 라벨도 확인했습니다 — 처음엔 `?????` 로 저장돼 서버 문제인가 했지만,
UTF-8 로 정확히 보내 다시 해보니 `한글 라벨 확인` 이 8글자로 제대로 저장됐습니다.
**서버는 정상이고, 제가 쓴 도구가 한글을 깨뜨린 것**이었습니다.

## 남은 이야기

**하루 한도는 아직 완전하지 않습니다.** 키를 붙이지 않으면 한도가 적용되지 않습니다.
실제로 막으려면 키를 필수로 하거나 IP 단위 제한을 넣어야 하는데, 이건 "누구나 바로 써 보는 공개 API"
라는 성격과 맞바꾸는 결정이라 상의가 필요합니다.

그 밖에 점검에서 뽑아 둔 것 두 가지가 남아 있습니다 — 기계가 읽는 규격(OpenAPI 3) 제공,
카탈로그에 에러 코드 표 넣기.
