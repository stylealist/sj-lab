## 작업 내용

시설물 레이어는 `zIndex: 1010`으로 고정돼 있어 지금은 가장 위였지만(다른 레이어 최대 1000), **값이 10 차이라 새 레이어가 조금만 높게 들어와도 핀이 가려지는 구조**였습니다. 값 자체를 올리고, 자동 보정을 넣었습니다.

| 항목 | 파일 | 내용 |
|---|---|---|
| 기본값 상향 | `js/modules/map/map-facility.js` | `zIndex: 1010` → 상수 `FACILITY_LAYER_Z_INDEX = 1500`. 다른 레이어(WFS·WMS 1000, 영역 선택 999~1000, 측정·배경 0)와 충분히 벌림 |
| 자동 보정 | 〃 | `keepFacilityLayerOnTop()` 신설 — 지도의 레이어 컬렉션 `add`/`remove` 이벤트마다 다른 레이어의 최대 zIndex 를 다시 계산해, 더 높은 레이어가 생기면 `FACILITY_LAYER_Z_MARGIN`(10)만큼 위로 올림. `setZIndex`는 add/remove 이벤트를 일으키지 않아 순환 호출이 없음 |
| 문서 | `docs/map-architecture.md` | 시설물 레이어 규격의 zIndex 항목을 "항상 최상단 + 자동 보정"으로 교체. **시설물 레이어의 zIndex 를 다른 곳에서 직접 바꾸지 말 것**(보정과 충돌) 명시 |

클러스터는 같은 레이어(`facilityLayer`)의 소스만 바꾼 것이라 이 설정을 그대로 따릅니다 — 핀이든 묶음 배지든 항상 최상단입니다.

## 검증 (로컬, 헤드리스 Chrome + CDP)

| 확인 | 결과 |
|---|---|
| 초기 상태 | 레이어 12개, zIndex `[0,0,0,0,1000×7,1500]` → **시설물 1500 최상단** |
| WFS 레이어 켠 뒤 | 그대로 1500 최상단 |
| `zIndex: 9000` 레이어를 일부러 추가 | 시설물이 **자동으로 9010** 으로 올라가 최상단 유지 |
| 그 레이어 제거 후 | 다시 1500 으로 복귀(무한정 올라가지 않음) |
| `node --check` | 통과 |
