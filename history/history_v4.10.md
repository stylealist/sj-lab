## 1. 무한 반복이 아니었습니다 — 서버가 뜨기를 기다린 것

서버 잡의 확인 단계는 **최대 5분까지 10초마다 다시 확인**합니다. 로그가 계속 쌓여서 멈춘 것처럼
보였지만, 파드가 올라오자 통과하고 **빌드 #1 이 성공**으로 끝났습니다.

```
Jenkins PROD-SJ-LAB-ESTATE  #1  SUCCESS
GET https://api.sj-lab.co.kr/estate/status → 200
{"ready":false, "message":"부동산 데이터 접속이 준비되지 않았습니다.", "propertyTypes":[아파트/오피스텔/빌라]}
```

| 조각 | 상태 |
|---|---|
| 이미지 빌드·push | 완료 |
| 클러스터 배포 | 완료(파드가 서비스 목록에 등록됨) |
| 주소 연결(게이트웨이) | 완료 |
| **DB 접속** | **아직** — `ready:false` |

설계한 대로입니다. 접속 정보가 없어도 **서비스는 뜨고** 조회만 막히며, 화면은 "준비되지 않았다"고
안내합니다. 그래서 잡도 실패가 아니라 경고만 찍고 성공으로 끝났습니다.

## 2. 개발 DB = 운영 DB 였습니다

같은 인스턴스라는 것을 확인했습니다. 좋은 점과 조심할 점이 같이 생깁니다.

- **표·뷰는 이미 다 있습니다** — 운영용으로 스크립트를 또 돌릴 필요가 없습니다(2,100만 건 그대로).
- 대신 **로컬에서 수집 배치를 띄우면 운영 데이터에 적재**되고, 조회해서 보는 숫자도 운영 숫자입니다.
- 이 사실을 총괄 문서와 작업 규칙에 적어 두었습니다(다음에 들어오는 사람이 모르고 띄우지 않게).

## 3. 남은 건 접속 계정 하나

서비스에 **개인 계정을 넣지 않기 위해** 조회 전용 계정 스크립트를 만들었습니다
(`db/estate/estate_read_role.sql`, 담당자 실행).

| 대상 | 권한 |
|---|---|
| 스키마 `estate` | 접속(USAGE) |
| 매매·전월세 표, 월별 집계 뷰 2개 | 읽기(SELECT) |
| 시군구 이름 표(`public.g_sgg`) | 읽기(SELECT) |
| 앞으로 추가될 estate 표 | 자동 읽기(기본 권한) |

쓰기 권한은 주지 않습니다 — 적재는 수집 배치가 하고, 이 서비스는 커넥션도 읽기 전용으로 엽니다.
오피스텔·빌라 표가 나중에 생겨도 권한을 또 줄 필요가 없게 해 두었습니다.

이어서 할 일(명령은 `docs/k8s-secrets.md` 에 그대로 적어 두었습니다):

```
계정 생성 → Secret 생성(접속 주소는 클러스터 안 서비스 이름) → 파드 재시작 → status 가 ready:true
```
