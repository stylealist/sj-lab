## 실행한 프롬프트

## 원인

상세 팝업은 `헤더 → 배지줄 → 본문(.facility-popup-body, max-height 440px, 스크롤)` 구조였고, 내업 처리 섹션이 그 **본문 맨 아래**에 붙어 있었습니다. 상세 항목이 19줄이라(스크롤 높이 1,317px) 끝까지 내리기 전에는 내업 기능이 있는지조차 알 수 없었습니다.

## 변경된 결과물

| 파일 | 변경 |
|---|---|
| `js/modules/map/map-facility.js` | 내업 섹션을 본문이 아니라 팝업 직계 자식(`#facilityOfficeFooter`)에 넣도록 변경. 팝업을 열 때마다 이 영역을 비우고(`clearFacilityOfficeFooter()`), 보수 필요 시설물일 때만 채움. 폼을 열면 이 영역의 `scrollTop`만 조정 |
| `css/components/layer-panel.css` | 팝업을 세로 플렉스로: 헤더·배지줄 고정, 본문 `flex:1; min-height:0` 스크롤, 내업 영역 하단 고정. 높이 상한을 본문이 아닌 팝업 전체(`min(600px, 100vh - 170px)`)에 적용, 내업 영역은 `min(300px, 45vh)` 안에서 자체 스크롤 |
| `docs/map-architecture.md`, `docs/ui-conventions.md` | 팝업 레이아웃(헤더·본문·고정 내업 영역)과 주의점 |

|---|---|---|
| 팝업 높이 | 600px (151~751) | 600px (101~701) |

| 본문 끝까지 스크롤(scrollTop 901) 후 | 같은 자리 고정 | 같은 자리 고정 |

기존 동작 회귀 확인(1600×900): 작성 폼을 열면 내업 영역이 300px로 늘고 내부 스크롤(755px)로 저장 버튼 접근 가능, 저장 `POST 201` → 목록 배지 `내업 완료`·건수 1 → 삭제 `DELETE 204` → `내업 미완료`·0건 복구, 헤더 드래그 −120px 이동, 닫기 버튼 동작, 팝업 표시 지연 로직 정상. 콘솔·페이지 오류 0건. 검증용 기록은 모두 삭제해 DB 활성 0건.
