## 화면에 "내 API 키"가 없던 이유

**로컬을 보고 계셨기 때문**입니다. 코드는 처음부터 다 되어 있었습니다.

```
운영  keys/status → ready: true    → 키 영역 보임
로컬  keys/status → ready: false   → 안 보임
```

화면은 `ready`가 참일 때만 키 목록·발급 버튼을 그립니다. v3.6에서 켠 것은 운영뿐이고,
로컬에 띄워 둔 공개 API 서버는 키 기능이 꺼진 채였습니다.

## 1. DB 계정을 전용 계정으로 분리

전에는 운영·로컬 모두 **개인 superuser 계정**을 쓰고 있었습니다. `api` 스키마 두 표에만
권한이 있는 전용 계정(`openapi_svc`)으로 바꿨습니다.

| 대상 | 권한 |
|---|---|
| 스키마 `api` | USAGE |
| 표 2개 | SELECT · INSERT · UPDATE |
| 시퀀스 2개 | USAGE · SELECT |
| 계정 속성 | superuser 아님, DB·역할 생성 권한 없음 |

`DELETE`는 필요 없습니다 — 키 폐기는 행을 지우는 게 아니라 "사용 안 함"으로 바꾸는 것이라서요.

**부여한 권한만으로 전부 동작하는지 운영에서 실제로 확인했습니다.**

```
파드 기동 · keys/status     ready=true   (새 계정으로 접속 성공)
키 발급                     OK           (INSERT + 시퀀스)
그 키로 호출 3회             200·200·200  (사용량 INSERT + 마지막사용 UPDATE)
목록 · 사용량                오늘 3/1000  (SELECT)
키 폐기                     OK           (UPDATE)
공개 조회                    200          (영향 없음)
```

## 2. 로컬도 키 기능이 켜지게

공개 API 서버를 전용 계정으로 다시 띄워 **로컬에서도 발급 → 호출 → 사용량 → 폐기**가 됩니다.
비밀번호는 `settings.local.json`(깃 제외 파일)에서 읽어 넣었고, 화면·명령문에 남기지 않았습니다.

여기서 한 걸음 더 나가, **기동 스크립트가 공개 API 서버도 함께 띄우게** 했습니다.
전에는 이 서버만 손으로 따로 띄워야 했습니다.

| | 전 | 후 |
|---|---|---|
| 기동 대상 | 5개 (Eureka · 백엔드 · 로그인 · 게이트웨이 · 프론트) | **6개** (공개 API 추가) |
| 공개 API | 손으로 `java -jar ...` | `start` 한 번에 8110 |
| 키 기능 | 매번 환경변수 직접 주입 | **비밀값 파일에 있으면 자동으로 켜짐** |
| `status` | 포트 3개 | 포트 4개 + **키 기능 켜짐/꺼짐 표시** |

비밀값이 없으면 **키 기능만 꺼진 채로** 정상 기동합니다(공개 조회는 그대로). 값이 반쯤 들어가
기동이 실패하는 일이 없도록 셋이 다 있을 때만 켭니다.

## 겪은 것 하나

Secret 만들기가 셸 오류(`event not found`)로 두 번 막혔습니다. 원인은 **여는 따옴표 하나**가
빠져서 뒤따르는 비밀번호가 따옴표 밖으로 밀려나고, 비밀번호 안의 `!` 가 bash 히스토리 확장으로
해석된 것이었습니다. 따옴표를 채워 해결했고, 비밀번호를 명령줄에 남기지 않는 방법도 함께 정리했습니다.

## 남은 이야기

- **개인 superuser 계정 비밀번호는 아직 교체 대상입니다.** 이제 운영·로컬 어디서도 그 계정을
  쓰지 않으니 안전하게 바꿀 수 있습니다.
- **하루 한도는 여전히 키를 붙인 호출에만 적용됩니다**(키를 빼면 우회). 키 필수화나 IP 제한은
  "누구나 바로 써 보는 공개 API"라는 성격과 맞바꾸는 결정이라 상의가 필요합니다.
