## 1. 조건으로 거르기 (지도)

검색창 옆에 **조건** 단추가 생겼습니다 — **평형 · 가격 · 연식**.

서울 한 구만 당겨도 말풍선이 수백 개라, 조건이 없으면 눈으로 하나씩 읽어야 했습니다.

- **서버에 다시 묻지 않습니다.** 이미 받아 둔 핀 안에서 거르므로 **누르는 즉시** 바뀝니다.
  대신 **"75개 중 12개"** 처럼 적어 둡니다 — 핀이 확 줄었을 때 "이 동네에 아파트가 없다"로
  읽히지 않게 하려고요.
- **가격을 고르면 전월세만 있는 단지(청록 말풍선)는 숨깁니다.** 그 금액은 매매가가 아니라
  보증금이라, 같은 자로 재면 "싼 아파트"로 둔갑합니다. 그 사실을 화면에 적어 둡니다.
- **보고 있던 단지는 조건과 무관하게 남습니다** — 사라지면 왼쪽 상세만 남아 어디 것인지 모릅니다.

## 2. 관심 단지 · 비교 · 그리고 회원 기능

왼쪽 패널에 **"내 단지"** 탭이 생겼습니다. 안에 작은 탭 네 개가 있습니다.

| | 하는 일 |
|---|---|
| **관심** | 담아 둔 단지. **"새 거래 3"** 처럼 담은 뒤 올라온 실거래를 알려 줍니다 |
| **최근** | 내가 열어 본 단지를 순서대로(최대 30개) |
| **메모** | 단지마다 적어 둔 내 한마디 |
| **내 정보** | 계정과 개수, 새 거래가 있는 단지 수 |

- 단지를 열면 맨 위에 **☆ 관심 담기**와 **✎ 메모**가 생깁니다(로그인했을 때만).
- **비교는 관심 단지에서 2~4개를 골라** 가운데 창에 **나란히** 놓습니다. 평형·평균가·준공·거래
  건수·내 메모를 같은 줄에서 견주고, **줄마다 가장 좋은 값을 파랗게** 칠합니다.
- **계정에 저장합니다** — 브라우저가 아니라 서버에 담기니 **다른 기기에서도 그대로** 보입니다.
  로그인은 기존 sj-lab 계정을 그대로 씁니다.

## 3. 새 서비스를 만들지 않았습니다

회원 데이터는 "써야" 하는데 부동산 서버는 **조회 전용**이었습니다. 보통이라면 서버를 하나 더
만들지만, 그러면 **배포 설정 · 빌드 잡 · 배포 등록**이 세트로 따라옵니다.

대신 **이미 같은 일을 하는 곳의 방식을 따랐습니다** — 지도 백엔드도 조회 서비스지만 현장
시설물의 "내업 기록"은 직접 씁니다.

- 실거래용 연결은 **읽기 전용 그대로** 두고, 회원용으로 **작은 연결을 따로** 엽니다
- DB 권한도 그렇게 나눕니다 — 실거래는 **읽기만**, 회원 영역에만 쓰기
- 그래서 **배포 설정은 한 줄도 바뀌지 않았습니다**

## 4. "새 거래"는 어떻게 세는가

알림을 따로 저장하지 않습니다. 관심 단지를 담을 때 **"그 시점의 가장 최근 계약일"** 을 적어 두고,
목록을 그릴 때 그보다 뒤의 거래를 셉니다. 그 단지를 열어 보면 기준이 올라가 표시가 사라집니다.

- **단지마다 따로 묻지 않습니다** — 관심 단지가 40개면 왕복이 80번입니다. 한 번에 가져옵니다.
- **지난주에 넣은 인덱스가 전제입니다**(v4.28). 없으면 단지 하나에 2초라 이 기능은 못 씁니다.
- 밀어 주는 알림(푸시·메일)은 아닙니다 — 화면에 들어왔을 때 배지로 보여 줍니다.

## 5. 확인한 것 · 남은 것

확인한 것

- 서버 **빌드·기동 통과**, 화면 **빌드 통과**
- 핀 거르개는 **이미 받은 핀으로만** 동작하므로 DB 와 무관하게 동작합니다

**남은 것 — DB 스크립트 한 번 실행**

- 회원 데이터를 담을 표가 아직 없습니다. 스크립트는 **`db/estate/estate_member.sql`**
  이고 **실행은 담당자**입니다(프로젝트 규칙).
- **실행 전에도 화면은 정상입니다** — 서버가 "아직 준비 안 됨" 으로 답하고 화면은 관심 단추를
  숨깁니다. 지도·시세는 전혀 영향이 없습니다.
- 실행하면 **재기동 없이** 켜집니다(60초마다 다시 확인).
- 그래서 **관심 담기·메모·비교는 아직 실제로 돌려 보지 못했습니다.** 숨기지 않고 적어 둡니다.
