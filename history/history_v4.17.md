## 1. 지금 할 수 있는 데까지 다 해 뒀습니다

핀 지도의 유일한 선행 조건은 **좌표**인데, 좌표를 받으려면 **공공 API 키 발급(사람이 신청)** 이
먼저입니다. 그래서 **키가 오면 바로 돌아가도록** 나머지를 모두 만들어 두었습니다.

| 만든 것 | 내용 |
|---|---|
| 단지 표 | `estate.apt_complex` — 주소 조각 + 좌표 + 받기 상태 (실행은 DB 담당자) |
| 단지 긁어오기 | 거래 표에서 단지를 뽑아 넣음. **여러 번 돌려도 받아 둔 좌표는 안 지워짐** |
| 좌표 받기 배치 | 행안부 → 실패분 VWorld 순서로 채움 |
| 진행 드라이버 | `scripts/estate-geocode.ps1` — 나눠 돌리기·진행 표시·재개 |
| 절차 문서 | 준비물, 명령, 확인 쿼리, 미리 막아 둔 함정 |

**대상은 거래 2,100만 건이 아니라 단지 44,581개**입니다(`apt_seq` 로 거래에 붙습니다).

## 2. 과거에 당한 함정을 코드로 막았습니다

작년 대량 수집에서 실제로 겪은 것들입니다.

| 함정 | 막은 방법 |
|---|---|
| 타임아웃이 없어 한 건에서 수십 분 멈춤 | 연결 5초 · 읽기 10초 고정 |
| **한도 초과를 빈 결과로 넘겨 조용히 구멍** | 한도면 **그 자리에서 중단**하고 알림. 기다렸다가 같은 자리에서 재개 |
| 끊겼는데 진행 위치만 앞으로 감 | **진행 위치를 파일에 두지 않음** — 상태가 DB 에 있어 구조적으로 불가능 |
| 로그 오류로 작업 자체가 죽음 | 로그 실패는 무시하고 계속 |
| 키가 로그·DB 에 남음 | 실패 사유는 **종류 이름만** 저장 |
| 같은 건을 끝없이 재시도 | 3회까지만 |

광주·전남 실거래가 비어 있는 것이 바로 두 번째 함정 때문이었습니다. 같은 일을 반복하지
않으려고 이번에는 처음부터 넣었습니다.

## 3. 좌표계를 조심했습니다

두 API 가 **서로 다른 좌표계로** 답합니다(행안부 5179 · VWorld 4326). 그대로 넣으면 지도에서
엉뚱한 곳에 찍힙니다 — 받은 좌표계를 함께 넘겨 DB(PostGIS)가 변환하게 했습니다.

확인 방법도 문서에 적었습니다: 서울이면 경도 126~127 · 위도 37 언저리여야 하고, 수십만 단위
숫자가 보이면 변환이 빠진 것입니다.

## 4. 남은 일 (사람이 하는 것)

1. **표 만들기** — `db/estate/estate_apt_complex.sql` (DB 담당자)
2. **키 신청** — 행안부 도로명주소 **좌표제공 API**(필수) · VWorld(선택). 둘 다 무료
3. **키 주입 후 실행** — `scripts\estate-geocode.ps1 -Sync` → `-Rounds 50`
4. 좌표가 모이면 지도 화면 — **핀 라벨(평형·가격)은 이미 만들어 둔 단지 API 로 바로 나옵니다**
