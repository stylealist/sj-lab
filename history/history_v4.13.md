## 실행한 프롬프트

```
estate-db-credentials 를 굳이 생성하지않고 기존에 생성한 Secret으로는 진행 안돼?
```

## 1. 기존 것으로 됩니다 — 조건이 하나 있습니다

이미 있는 **공개 API 의 접속 정보(`openapi-db-credentials`)를 그대로 쓰기로** 했습니다.
같은 DB 를 가리키고 항목 이름도 같아서, **배포 설정 한 줄만 바꾸면** 됩니다.
그래서 **클러스터를 직접 만질 일이 없어졌습니다**(설정을 올리면 배포 도구가 알아서 반영).

조건은 하나입니다 — 그 계정은 공개 API 용으로 만들어져 **부동산 데이터를 읽을 권한이 없습니다.**
확인한 결과:

| 확인 | 결과 |
|---|---|
| 그 계정의 부동산 스키마 접속 | ✗ 없음 |
| 그 계정의 매매 표 읽기 | ✗ 없음 |
| 그 계정의 공개 API 표 읽기 | ✓ (원래 용도) |

그래서 **읽기 권한만 주는 SQL 한 번**이 필요합니다 — 쓰기 권한은 주지 않습니다.

## 2. 그 과정에서 함정 하나를 미리 막았습니다

계정을 바꾸다 보니, **권한이 없어도 "정상"으로 보고될 수 있는** 구멍이 보였습니다.

- 종전 준비 확인은 **통계 정보**를 한 줄 읽었는데, 그 통계는 **권한이 없는 계정도 읽을 수 있습니다.**
- 그대로 두면 화면은 "정상"인데 **조회만 전부 실패**하는, 가장 헷갈리는 상태가 됩니다.
- 그래서 확인 방식을 **실제 표에서 한 행 읽기**로 바꿨습니다. 권한이 없으면 바로 그렇게 보고합니다.

이제 상태가 셋 중 하나로 정확히 나옵니다.

| 상태 | 뜻 |
|---|---|
| 접속 정보 없음 | 아직 설정이 안 들어감 |
| **조회 실패** | 설정은 있는데 권한·주소 문제 ← SQL 실행 전이면 여기 |
| 정상 | 조회 가능 |

## 3. 남은 한 가지 (SQL 한 번)

DB 담당자가 아래를 한 번 실행하면 끝입니다. 읽기 권한만 주고, 확인 쿼리와 되돌리는 방법도
같은 파일에 적어 두었습니다.

```
db/estate/estate_grant_openapi_svc.sql
```

실행 후 `https://api.sj-lab.co.kr/estate/status` 가 "정상"이 되고 화면에 데이터가 채워집니다.
