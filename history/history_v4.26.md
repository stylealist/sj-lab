## 1. 무엇이 불편했나

**시군구를 먼저 골라야 단지를 찾을 수 있었습니다.** 단지 목록 API(`/complexes`)가 지역 코드를
필수로 받기 때문입니다. "래미안"처럼 **이름만 아는 경우**를 받지 못해, 사용자가 지도를 직접
끌고 다니며 찾아야 했습니다. 호갱노노식 지도에서 가장 큰 기능 공백이었습니다.

## 2. 지도 위에 검색창이 생겼습니다

단지명 일부를 넣으면 **전국에서 찾고**, 고르면 세 가지가 함께 일어납니다.

1. **지도가 그 단지로 날아갑니다**(핀이 보이는 배율까지 당깁니다)
2. **왼쪽에 단지 상세가 열립니다**
3. **지역 조건이 그 단지에 맞춰집니다**(다른 지역 단지를 골라도 바로 보입니다)

같은 이름의 단지가 많아서(44,616개 중 서로 다른 이름이 36,168개) 목록에 **시군구·읍면동과
준공연도, 거래 건수**를 함께 보여 줍니다. 좌표가 없는 단지(전체의 1.2%)는 **"위치 없음"** 을
붙입니다 — 고르면 지도가 움직이지 않아 아무 일도 안 일어난 것처럼 보이기 때문입니다.

**검색창은 지도 위 왼쪽 위에 떠 있습니다.** 처음에는 헤더에 넣었는데 ① 헤더 오른쪽이 이미 꽉 차
**둘째 줄로 밀려** 접기 버튼과 겹쳐 보이고 ② **헤더를 접으면 검색창도 사라져** 지도 위로 옮겼습니다.
왼쪽 패널을 접거나 펼치면 **패널과 같은 속도로 함께 비켜섭니다.**

키보드로만도 쓸 수 있습니다 — **↑·↓** 로 옮기고 **Enter** 로 고르고(아무것도 안 골랐으면 첫 결과)
**Esc** 로 닫습니다.

## 3. 느리지 않게 만드는 데 공을 들였습니다

**단지 표를 그냥 검색하면 944ms가 걸립니다**(실측). 그 표에 지도용 도형(`geom`·`boundary`)이
들어 있어 행이 넓고(약 36,000 페이지), 이름 부분검색은 인덱스를 쓸 수 없어 전수 조회가 되기
때문입니다. **키를 칠 때마다 1초가 걸리면 검색창으로 쓸 수 없습니다.**

그래서 **단지 표를 메모리에 올려 두고 거기서 찾습니다**(6시간마다 갱신, 약 7MB).
표가 44,616행뿐이라 전부 올려도 부담이 없습니다.

| | 소요 |
|---|---|
| DB 를 매번 검색 | 944ms |
| **메모리 색인** | **6~17ms** |

**거래 표가 아니라 단지 표를 읽습니다.** 거래 표는 990만 행이고 단지 키에 인덱스가 없어 전국
이름 검색이 애초에 불가능합니다. 단지 표는 좌표를 **98.8%** 들고 있어 고른 단지로 바로 날아갈
수 있습니다.

### 고치면서 발견한 것 — 예열 순서

색인 올리기(9초)를 기존 예열 뒤에 순서대로 붙였더니, **그 앞의 지역 목록 예열이 27초를 먹어
색인 차례가 너무 늦게 왔습니다.** 그 사이에 검색한 사람이 **13초를 기다리는 것**을 로그로
확인했습니다(색인 적재가 예열 스레드가 아니라 **요청 스레드**에서 돌았습니다).

**둘을 떼어 나란히 돌리도록 고쳤습니다.** 지금은 기동 직후 전용 스레드에서 8.9초에 끝나고,
사용자 요청은 기다리지 않습니다.

## 4. 확인한 것

- 백엔드 빌드 통과(JDK 17) · 프론트 빌드 통과(기존 번들 크기 경고만)
- 검색 **6~17ms**(색인 적재 후) · 1자 입력은 **0건**(한 글자로 전국을 뒤지지 않게)
- `q` 없음 → **400** · `limit=999` → **400**
- 순서 확인 — "은마" 는 **강남구 대치동(거래 17,361건)** 이 1등, 좌표 있는 단지가 먼저
- 공백 무시 확인 — **"래미안 퍼스티지"** 로 쳐도 "래미안퍼스티지" 가 찾힙니다
- 화면이 실제로 부르는 경로(dev server 프록시)로도 **14~15ms** 확인
- 좌표가 정확한지 확인 — 은마 `127.0655, 37.4974`(강남구 대치동), 지역코드 `11680`

## 5. 공개 API 에는 열지 않았습니다 (판단 필요)

프로젝트 규칙대로 공개 API(`sj-lab-openapi`)에 열 수 있는지 봤습니다. **네 가지 조건은 모두
만족합니다**(GET · 로그인 불필요 · 응답 작음(최대 50건) · 개인정보 아님).

다만 **공개 API 는 중계 대상이 `mapservice-rest` 하나**이고, 부동산(estate) 엔드포인트는
**아직 하나도 열려 있지 않습니다.** 이번 것을 열려면 두 번째 중계 대상을 새로 만드는
**구조 변경**이 됩니다. 규칙이 "애매하면 열지 말고 사용자에게 먼저 물어본다"이므로 **열지
않았습니다.** 부동산 데이터를 공개 API 로 열 생각이 있으시면 그때 함께 설계하는 것이 맞습니다.
