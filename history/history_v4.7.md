## 1. 무엇이 깨졌나

빌드·번들링까지는 정상이었고 **웹서버에서 파일을 옮기는 마지막 단계**에서 죽었습니다.

```
bash: -c: line 9: syntax error near unexpected token ';&'
```

원인은 두 가지가 겹친 것이고, 둘 다 **원격 서버에서 실행되는 명령**에만 해당합니다.

1. **꺾쇠(`>`)와 앰퍼샌드(`&`)가 글자 그대로 들어갔습니다.** 잡 설정 파일(XML)에서는 이 문자들이
   `&gt;` · `&amp;` 로 적혀 있는데, 그 내용을 **사람이 복사해 Jenkins 화면에 붙여 넣으면** 그대로
   들어갑니다. 원격 bash 가 `2&gt;&amp;1` 을 받고 문법 오류로 죽었습니다.
2. **임시 폴더 이름의 `$$`가 `$`로 줄었습니다.** 파일을 보내는 플러그인이 명령문 안의 변수를
   먼저 치환하기 때문입니다(로그에 `${DST}.new.$` 로 찍혔습니다).

## 2. 어떻게 고쳤나

**원격 명령에서는 꺾쇠·앰퍼샌드·`$$`를 아예 쓰지 않도록** 다시 썼습니다. 리다이렉션과 `&&`·`||`
대신 `if` 문만 씁니다 — 같은 일을 하면서 어떤 방식으로 잡에 넣어도 깨지지 않습니다.

- 잡 설정 파일(XML)도 다시 만들었습니다
- 왜 그렇게 쓰는지, 잡에 넣을 때 **무엇을 복사해야 하는지**를 `docs/jenkins/README.md` 에 적었습니다
  — 다음에 또 같은 함정에 빠지지 않게 하는 것이 이번 작업의 본질입니다

> **잡에 넣을 때는 `*-pipeline.groovy` 파일을 그대로 붙여 넣으세요.** 설정 파일(XML)은 명령으로
> 등록할 때만 씁니다(그 경로에서는 Jenkins 가 알아서 되돌립니다).

## 3. 지금 `/estate/` 가 403 인 이유

실패한 스크립트가 **폴더를 만든 뒤**(`mkdir`) 죽어서 **빈 `html/estate` 폴더가 남았습니다.**
그래서 주소를 열면 404 가 아니라 **403**(폴더는 있는데 보여 줄 파일이 없음)이 됩니다.
배포가 한 번 성공하면 해결되므로 따로 지울 필요는 없습니다.

증상으로 외워 두면 편한 표(문서에도 넣었습니다):

| `/estate/` 응답 | 뜻 |
|---|---|
| 404 | 폴더도 없음 = 한 번도 배포 안 됨 |
| **403** | 폴더는 있고 파일이 없음 = **배포가 중간에 실패**(지금 상태) |
| 200 + 허브 화면 | 파일이 없고 웹서버 경로 설정도 아직 반영 전 |
| 200 + 부동산 화면 | 정상 |
